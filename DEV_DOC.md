# Developer documentation

This guide describes how to prepare, build, run, and maintain the Inception stack from a clean checkout.

## Prerequisites

- A Linux virtual machine (the project is intended to run inside a VM).
- Docker Engine and the Docker Compose plugin.
- GNU Make and OpenSSL.
- A host account with a home directory under `/home/`; the current user's `USER` environment variable is used to derive the persistent data paths. It normally matches the output of `whoami`.

Confirm Docker is available to your account with `docker version` and `docker compose version`. If your account needs Docker group membership, configure that on the VM according to your system's Docker installation instructions.

## Configuration and secrets

The root `Makefile` invokes Compose with `srcs/docker-compose.yml`. The Compose file reads non-secret variables from `srcs/.env`; currently these include `DOMAIN_NAME`, `MYSQL_DATABASE`, and `MYSQL_USER`. Review this file before starting and keep its domain consistent with the NGINX virtual host and certificate subject.

Sensitive values are generated by the `secrets` Make target into local files under `secrets/`:

- `db_password.txt`
- `db_root_password.txt`
- `credentials.txt`
- `ftp_password.txt`

Do not commit these files or put credentials in a Dockerfile, Compose environment variable, or `srcs/.env`. Compose mounts the files into only the services that need them.

The Compose file interpolates `${USER}` for the host data directories. The Makefile uses the same variable when it creates those directories. In a normal login shell, it is already set to the current account, which you can confirm with:

```sh
whoami
printf '%s\n' "$USER"
```

The two values should identify the same account. If `USER` is missing or differs, set it to the output of `whoami` in the shell before running `make up`. The volume paths then resolve to `/home/<current-user>/data/{mariadb,wordpress,redis}`. For FTP clients outside the Docker host, set `FTP_PASV_ADDRESS` in the environment to the VM's reachable IP before starting the stack; its current default is `127.0.0.1`.

## Build and launch

From the repository root:

```sh
make up
```

The Makefile creates missing secrets, creates host directories for the database, WordPress files, and Redis, then runs `docker compose -f srcs/docker-compose.yml up --build -d`. Each service image is built from its own Dockerfile under `srcs/requirements/`.

Set up name resolution for the configured domain, `mboutte.42.fr`, on the client machine so it points to the Docker host or VM IP. If you change the domain, keep `srcs/.env`, `srcs/requirements/nginx/conf/nginx.conf`, and the certificate subject in `srcs/requirements/nginx/tools/entrypoint.sh` consistent. NGINX listens on 443 and generates a self-signed certificate when needed.

## Useful management commands

```sh
# Show service state
docker compose -f srcs/docker-compose.yml ps

# Follow logs
docker compose -f srcs/docker-compose.yml logs -f
docker compose -f srcs/docker-compose.yml logs -f nginx

# Rebuild and recreate one service
docker compose -f srcs/docker-compose.yml up --build -d --force-recreate wordpress

# Stop and remove containers/network; retain named-volume data
make down

# Stop containers without removing them
make stop

# Show service state (no Make target exists)
docker compose -f srcs/docker-compose.yml ps

# Restart one stopped service (no Make target exists)
docker compose -f srcs/docker-compose.yml start wordpress
```

`make clean` runs `docker system prune -af` after stopping the project, which can remove unrelated unused Docker resources on the same machine. `make fclean` additionally deletes `~/data/*` and the root `secrets/` directory. Those operations can permanently remove project data or credentials; use them only when that is intended. Do not use `make re` unless you intend the same full cleanup followed by a fresh start.

## Persistent data

Compose defines named volumes backed by the local volume driver with bind options. Their data is stored at:

| Compose volume | Container path | Host path |
| --- | --- | --- |
| `db_data` | `/var/lib/mysql` | `/home/<current-user>/data/mariadb` |
| `wp_data` | `/var/www/html` | `/home/<current-user>/data/wordpress` |
| `rds_data` | `/data` | `/home/<current-user>/data/redis` |

The MariaDB volume preserves the database, the WordPress volume preserves site files and uploads, and the Redis volume preserves its append-only data. `make down` removes containers but leaves these host directories intact. Back up the host directories before maintenance that might affect storage.

The Compose file also declares `netdataconfig`, `netdatalib`, and `netdatacache`, but does not currently attach them to the Netdata service. Netdata configuration, library data, and cache therefore are not persisted using those declarations.

## Services and ports

All services join the `inception` bridge network and can resolve one another by service name. NGINX is the public entry point for WordPress on port 443. Bonus ports are separately published: Adminer 8080, Redis 6379, static website 4242, Netdata 19999, and FTP 21 plus passive ports 30000–30009. The FTP passive address must be reachable by clients.
